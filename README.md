# 长理失物招领墙

面向长沙理工大学的校园失物招领网页。丢失者和拾获者可以在这里发布信息，系统会自动比对「丢失」与「招领」记录，给出潜在匹配清单，帮助物品更快回到失主手中。

项目是一个**纯静态单文件应用**：所有 HTML、CSS、JavaScript 都集中在 `index.html` 中，无需构建、无需后端、无需任何第三方依赖，用浏览器打开即可使用。

## 功能特性

- **发布信息**：支持「丢失」「招领」两种类型，登记物品名称、发生地点、发生时间、特征描述和联系方式。
- **表单校验**：必填校验、长度限制（名称 30 / 地点 50 / 特征 200 / 联系方式 50 字）、时间不得晚于当前时间，错误信息即时提示。
- **分类筛选**：按「全部 / 丢失 / 招领」切换查看。
- **潜在匹配**：自动比对丢失与招领记录，综合物品名称相似度、特征关键词重合度和时间接近程度给出匹配结果，并按可信度排序。
- **状态标记**：可对单条信息或一对匹配标记「已找到」，配对双方同时生效。
- **本地持久化**：数据保存在浏览器 `localStorage` 中，刷新页面不丢失。
- **安全处理**：用户输入仅以纯文本写入页面（`textContent`），不使用 `innerHTML` / `eval` 等危险接口；恢复本地数据时按白名单逐字段重建，不向任何服务器发送数据。
- **响应式布局**：适配桌面与移动端，支持键盘操作与无障碍属性。

## 快速开始

方式一：直接双击 `index.html`，用现代浏览器打开。

方式二：在项目目录启动一个本地静态服务器：

```bash
# 任选其一，端口可按需修改
python -m http.server 8000
# 或
npx serve .
```

然后访问 `http://localhost:8000/`。

## 数据存储说明

- 数据写入 `localStorage` 的 `csuLostFound.dataset` 键，数据结构带 `version` 字段用于格式演进。
- 数据仅存在于当前浏览器，不会上传服务器；**清理浏览器数据或更换设备后信息不会保留**。
- 联系方式会公开展示在信息卡片上，发布时请谨慎填写。

## 匹配规则概述

匹配引擎是纯函数实现，主要依据：

1. **名称相似度**：对名称做全角转半角、大小写与空白归一化后，判断完全相同、包含关系或字符覆盖度。
2. **特征关键词**：从特征描述中提取关键词（过滤无意义停用词），比较双方关键词的重合情况。
3. **时间接近度**：同一自然日的记录会获得更高的匹配权重。

综合以上维度为每对「丢失 + 招领」记录评分分级，只展示仍处于「寻找中」状态的记录。

## 技术栈

- 原生 HTML5 + CSS3 + JavaScript（ES5 风格，无框架、无构建工具）
- 浏览器 `localStorage` 本地存储

## 浏览器兼容

支持所有现代浏览器（Chrome、Edge、Firefox、Safari 及主流国产浏览器）。需启用 `localStorage`；在隐私模式或禁用本地存储的环境下，页面仍可使用，但数据不会被保存。

## 部署

项目为纯静态页面，可直接部署到 GitHub Pages、Gitee Pages、对象存储静态站点托管等任意静态托管服务。启用 GitHub Pages 后地址形如 `https://<用户名>.github.io/<仓库名>/`。
