# 学校失物招领墙

面向学校的失物招领网页。丢失者和拾获者可以在这里发布信息，系统会按**名称、特征、地点、时间**四个维度自动比对「丢失」与「招领」记录，给出带评分与命中原因的潜在匹配清单，帮助物品更快回到失主手中。

技术栈：**Vue 3 + Vite**，纯前端、无后端、无 UI 框架依赖，数据保存在浏览器 `localStorage`，构建产物为静态文件，可直接部署到 GitHub Pages。

## 功能特性

- **发布信息**：支持「丢失」「招领」两种类型，登记物品名称、地点、时间、特征描述和联系方式。
- **表单校验**：必填校验、长度限制（名称 30 / 地点 50 / 特征 200 / 联系方式 50 字）、时间不得晚于当前时间，错误项自动聚焦。
- **关键字搜索**：按名称、地点、特征检索，支持空格分隔的多关键词 AND 组合，大小写不敏感。
- **组合筛选**：全部 / 丢失 / 招领 +「仅看寻找中」开关。
- **统计概览**：寻找中、招领中、已找回、潜在匹配四项实时指标。
- **智能匹配**：输出 0~100 综合分与高 / 中 / 一般三档等级，展示命中原因（名称一致 / 名称相近 / 特征重合 / 地点相同 / 同日发生）与重合关键词。
- **状态标记**：单条信息或一对匹配可标记「已找到」，配对双方同步生效，匹配清单自动更新。
- **隐私保护**：联系方式在卡片上默认遮罩，点击「查看」才显示。
- **本地持久化**：刷新页面自动恢复数据，存储失败、数据损坏均有兜底提示。
- **界面反馈**：操作 Toast、列表与匹配卡片过渡动画、空状态引导，支持响应式与减少动画偏好。

## 匹配评分模型

每对「丢失 × 招领」记录按四个维度加权得到 0~100 综合分：

| 维度 | 权重 | 说明 |
|---|---|---|
| 名称 | 45% | 归一化后判完全相等（1.0）、连续包含（0.8~1.0）、单字包含（0.55）、字符覆盖（≤0.75）、编辑距离相似（≤0.6） |
| 特征 | 25% | 优先匹配内置词典关键词重合度，未命中片段用字符 bigram Jaccard 相似度兜底；特征为空不再一票否决 |
| 地点 | 15% | 归一化后相同（1.0）、包含（0.8）、bigram 重合分档 |
| 时间 | 15% | 同日（1.0）/ 3 天内（0.75）/ 7 天内（0.5）/ 30 天内（0.25），缺失给中性分 |

补充规则：

- **单字名称召回需佐证**：如「伞」与「雨伞」只有在特征词典重合或地点高度一致时才入围，避免误配。
- **先丢后捡约束**：招领时间早于丢失时间的配对按 0.6 系数降权，并展示「时间顺序存疑」标签。
- **入围门槛**：综合分 ≥ 35；等级映射 ≥ 75 高、≥ 55 中、其余一般。
- 仅「寻找中」状态的信息参与匹配，结果按分数降序、时间差升序排列，最多展示 50 对。

## 数据存储说明

- 数据写入 `localStorage` 的 `csuLostFound.dataset` 键，结构带 `version` 字段用于格式演进；恢复时按白名单逐字段重建，非法或重复记录跳过并提示。
- 数据仅存在于当前浏览器，不会上传服务器；**清理浏览器数据或更换设备后信息不会保留**。
- 联系方式会随信息保存，发布时请谨慎填写。

## 界面设计

采用 Minimalist Modern 视觉系统：暖白画布 `#FAFAFA`、深 slate 正文 `#0F172A`、电蓝主色 `#0052FF → #4D7CFF` 渐变、匹配面板使用深色反转区块与点阵纹理；字体以系统字体栈实现 Display / Body / Mono 三层分工，不加载外部字体，离线可用。

## 后续优化路线

- **阶段二**：物品品类 / 地点区域筛选、图片本地压缩上传、JSON 数据导出备份。
- **阶段三（引入后端）**：账号体系、认领审核、订阅通知。届时只需将 `src/services/storage.js` 替换为 HTTP 实现，组件与匹配引擎零改动。轻量后端可参考云开发或 Supabase / Firebase 路线。

方向参考的同类开源项目：`gongsir0630/LostAndFoundOnCampus`（检索 / OCR / 订阅通知）、`yangxuechen/LostAndFound`（云开发）、`shobithirunavukarasu/campus-lost-and-found`（Firebase 认领流程）、`nature924/No4Campus-lost-and-found-system`（前后台与角色划分）。

## 部署

`npm run build` 后将 `dist/` 部署到任意静态托管服务。Vite 已配置 `base: './'`，可直接用于 GitHub Pages 项目页（形如 `https://<用户名>.github.io/<仓库名>/`）或子目录托管。
