# 学校失物招领墙

面向学校的失物招领网页。丢失者和拾获者可以在这里发布信息，系统会按**名称、特征、地点、时间**四个维度自动比对「丢失」与「招领」记录，并叠加品类与颜色负信号，给出带评分、命中原因与差异提示的潜在匹配清单，帮助物品更快回到失主手中。

技术栈：**Vue 3 + Vite**，纯前端、无后端、无 UI 框架依赖，数据保存在浏览器 `localStorage`，支持 JSON 备份与恢复，构建产物为静态文件，可直接部署到 GitHub Pages。

## 功能特性

**信息发布与管理**
- 发布「丢失」「招领」两类信息：名称、地点、时间、特征描述、联系方式。
- 表单校验：必填、长度限制（名称 30 / 地点 50 / 特征 200 / 联系方式 50 字）、时间不得晚于当前时间，错误项自动聚焦。
- **编辑信息**：复用发布表单回填，`seq`、创建时间与状态保持不变，匹配自动重算。
- **删除信息**：卡片内联二次确认，避免误删。
- **清空数据**：二次确认后清空列表与本地存储。

**检索与浏览**
- 关键字搜索：按名称、地点、特征检索，空格分隔多关键词 AND 组合，大小写不敏感。
- 组合筛选：全部 / 丢失 / 招领 +「仅看寻找中」，支持一键重置条件。
- 统计概览：寻找中、招领中、已找回、潜在匹配四项实时指标。

**智能匹配**
- 0~100 综合分 + 高 / 中 / 一般三档等级，评分条可视化。
- 命中原因标签：名称一致 / 名称相近 / 特征重合 / 地点相同 / 同日发生。
- **差异提示标签**：品类不同 / 颜色不同 / 地点不同 / 时间跨度大 / 时间顺序存疑，辅助人工判断。
- 信息卡显示「N 条潜在匹配」徽标，点击滚动定位到对应配对并高亮；点击配对任一侧可反向定位信息卡。
- 单条信息或一对匹配可标记「已找到」，配对双方同步生效。

**便捷操作**
- 时间默认填当前时刻；常用地点一键填入、常用特征一键插入。
- 联系方式默认遮罩，支持查看与**一键复制**。
- 「提交并再发一条」连续发布，保留上次信息类型。
- 操作 Toast 反馈、列表与匹配卡片过渡动画、空状态引导。

**数据安全**
- 本地持久化：刷新自动恢复，存储失败、数据损坏均有兜底提示。
- **导出备份**：下载含版本号的 JSON 文件。
- **导入恢复**：白名单归一校验，重复内容自动跳过，`seq` 冲突自动重新编号，报告"新增 / 重复 / 无效"条数。
- 旧版存储键自动迁移，历史数据不丢失。

## 匹配评分模型

每对「丢失 × 招领」记录按四个维度加权得到基础分，再乘以负信号系数，得到 0~100 综合分：

| 维度 | 权重 | 说明 |
|---|---|---|
| 名称 | 45% | 归一化后判完全相等（1.0）、连续包含（0.8~1.0）、单字包含（0.55）、字符覆盖（≤0.75）、编辑距离相似（≤0.6） |
| 特征 | 25% | 优先匹配内置词典关键词重合度，未命中片段用字符 bigram Jaccard 相似度兜底；特征为空不再一票否决 |
| 地点 | 15% | 归一化后相同（1.0）、包含（0.8）、bigram 重合分档 |
| 时间 | 15% | 同日（1.0）/ 3 天内（0.75）/ 7 天内（0.5）/ 30 天内（0.25），缺失给中性分 |

**负信号（乘性降权，不强制排除）**

| 信号 | 系数 | 说明 |
|---|---|---|
| 品类冲突 | ×0.75 | 由名称与特征推断品类（电子数码 / 证件卡片 / 雨具 / 包袋等），双方品类不同 |
| 颜色冲突 | ×0.8 | 双方都提到颜色且毫无交集（如"黑色" vs "白色"）；一方未提颜色不处罚 |
| 跨日顺序存疑 | ×0.6 | 招领时间早于丢失时间且跨日；超过 7 天降为 ×0.4 |
| 同日顺序存疑 | 不降权 | 丢失时间本是估计值，同日内"捡到早于丢失"属正常误差 |

补充规则：

- **单字名称召回需佐证**：如「伞」与「雨伞」只有在特征词典重合或地点高度一致时才入围。
- **入围门槛**：综合分 ≥ 35；等级映射 ≥ 75 高、≥ 55 中、其余一般。
- 仅「寻找中」状态的信息参与匹配，结果按分数降序、时间差升序排列，最多展示 50 对。

## 数据存储说明

- 数据写入 `localStorage` 的 `campusLostFound.dataset` 键，结构带 `version` 字段；恢复时按白名单逐字段重建，非法记录跳过并提示。
- 启动时若新键无数据，会自动读取旧版 `csuLostFound.dataset` 键并迁移：写入新键成功后删除旧键；新键已有数据则不触碰旧键。
- 数据仅存在于当前浏览器，不会上传服务器；**清理浏览器数据或更换设备后信息不会保留，请定期使用「导出备份」**。
- 导入支持多来源备份合并：内容相同的记录判重跳过，序号冲突自动重新编号。
- 联系方式会随信息保存，发布时请谨慎填写。

## 界面设计

采用 Minimalist Modern 视觉系统：暖白画布 `#FAFAFA`、深 slate 正文 `#0F172A`、电蓝主色 `#0052FF → #4D7CFF` 渐变、匹配面板使用深色反转区块与点阵纹理；字体以系统字体栈实现 Display / Body / Mono 三层分工，不加载外部字体，离线可用。联动定位以高亮描边 + 平滑滚动反馈。

## 后续优化路线

- **阶段二**：物品品类显式字段与筛选、图片本地压缩上传、匹配结果人工反馈（"不是同一物品"降权学习）。
- **阶段三（引入后端）**：账号体系、认领审核、订阅通知。届时只需将 `src/services/storage.js` 替换为 HTTP 实现，组件与匹配引擎零改动。轻量后端可参考云开发或 Supabase / Firebase 路线。

方向参考的同类开源项目：`gongsir0630/LostAndFoundOnCampus`（检索 / OCR / 订阅通知）、`yangxuechen/LostAndFound`（云开发）、`shobithirunavukarasu/campus-lost-and-found`（Firebase 认领流程）、`nature924/No4Campus-lost-and-found-system`（前后台与角色划分）。

## 部署

`npm run build` 后将 `dist/` 部署到任意静态托管服务。Vite 已配置 `base: './'`，可直接用于 GitHub Pages 项目页（形如 `https://<用户名>.github.io/<仓库名>/`）或子目录托管。
